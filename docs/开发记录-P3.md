# P3a 开发记录（托盘驻留，2026-10-02）

P3 的第一件事：**托盘驻留 + 关闭窗口的行为**（设置项「关闭窗口时：驻留托盘 / 直接退出」）。
范围与决策见 `docs/P3-实施方案.md`；本文只记实际做了什么、踩到什么、怎么验的。

## 1 做了什么

- **托盘图标**：雾青圆角方块 + 白色「L」，逐像素画（不引图片素材），tooltip「Lexideck — 词卡看板控制面板」。
- **左键单击** = 显示 / 隐藏面板；**右键** = 打开菜单（显示/隐藏面板、显示全部卡片、隐藏全部卡片、退出 Lexideck）。
- **关闭行为**：默认「驻留托盘」——点 ✕ = 面板收进托盘（卡片照留在桌面）；设置里可切「直接退出」（沿用 5 秒二次确认）。
- **真退出三条路**（都用一个 `exiting` 标记绕过关闭拦截）：面板「退出」按钮 / 托盘菜单「退出」/ `exit` 模式点两次 ✕。
- 托盘建不起来时自动退回「关闭 = 退出」，不会出现"面板藏了却没处唤回"把自己锁死的情况。

## 2 两个跟"系统级模态"有关的关键决策

### 2.1 「收进托盘」不能用隐藏窗口，必须挪到屏幕外

eframe 0.36 对「不可见 / 最小化」窗口会走一条直接补画的旁路（为修 egui#5229 的 Windows 问题所加）。
那条路**没有登记事件循环上下文**，于是「新建窗口」（= 新词卡上屏、从托盘显示全部卡片）会被静默跳过，
egui 随即断言崩：`egui backend is implemented incorrectly - the user callback was never called`。

实测（带 PDB 的 backtrace + 临时给 eframe 源码插调试输出定位）：

- 复现：面板隐藏时，从托盘点「显示全部卡片」必崩；课堂上新词到点上屏同样会崩。
- 定位：调试输出 `[eframe-dbg] render_immediate_viewport ...: NO current event loop context`。
- 处置：**「收进托盘」= 把窗口挪到 (-32000,-32000)**。窗口仍是「可见」态，所有帧走正常路径；
  `reconcile_floats` 里补一条：窗口最小化时先不建新浮窗，等恢复的下一帧再补。
- 验证：隐藏状态下从托盘新建浮窗不再 panic；唤回时**精确回到原位** (60,360)。

### 2.2 托盘右键菜单从系统原生改成自绘

muda 的原生菜单走系统级模态 `TrackPopupMenu`：**点完菜单项之后 winit 主循环会"冻住"**
（进程活着、消息泵在转、CPU 0%、一帧不跑，连 posted 的 WM_CLOSE 都不派发）。
winit 源码里对系统菜单冻结用的招数是给窗口发一条假鼠标移动，心跳线程照做后的对照实验：

- **不唤醒**：菜单能正常关，但应用"睡着"不执行动作 —— 7/7 全挂；
- **无脑唤醒**：会把原生菜单自己的模态循环打断，约 1/2 概率卡成「点不动的幽灵菜单」（点条目没反应、菜单不关）。

两难，且都是原生死路。最终方案：**整个弃用原生菜单** —— 右键改成自绘菜单
（`src/menu.rs`，就是一个普通即时视口，没有模态循环），从根上消灭这类问题；
样式还能和面板共用同一套 Theme。实测两轮 × 7 次菜单交互：**0 卡死、0 冻结**。
心跳（250ms；怀疑冻住时发一条假鼠标移动）保留为**通用保险**——系统文件对话框等其它模态路径
也可能触发"睡死"，留着它冻住也能自愈。

## 3 面板复审发现并修掉的两个缺陷（慕言真机反馈）

### 3.1 托盘隐藏面板后卡片变小、跑位

- 现象：卡片从 448×309 变成 336×232，位置从 (1444,34) 跑到 (1083,25)。
- 根因：面板挪到屏外后，系统把它算成「**最近的**显示器」（= 左边那块 1440×1080），
  屏幕系数从 1.0 掉到 0.75，平铺锚点也跟着换屏。
- 修法：屏幕尺寸「面板可见时读实时值并记住，收进托盘时用记住的值」；三个读取点统一走它。
- 验证：隐藏后卡片稳定在 448×309 @(1444,34)，唤回后照旧。

### 3.2 顶栏 ✕ / 最小化按钮悬浮时闪灰

- 现象：鼠标悬浮上去，按钮背景先闪一两帧深灰再到目标色（"会闪烁"）。
- 根因：淡入用了 `mix(Color32::TRANSPARENT, 色, t)` —— alpha 被一起插值、再预乘一次，
  过渡中段算出的中间色发灰。同点位像素采样实证：`BCBDBD → D1D2D2 → F9FAFB`。
- 修法：三处同一模式（顶栏按钮 ×2、卡片区按钮 ×1）全部改成 `色.gamma_multiply(t)`
  （颜色连同 alpha 等比缩 = 真正的淡入）。
- 验证：同点位采样变成 `F5F7F8 → F8F9FA → F9FAFB`，全程浅色、无灰帧。

## 6 P3b · 开机自启（2026-10-02）

### 6.1 事实以注册表为准

设置页那个开关**不缓存自己的状态**：每次进设置页（`panel.autostart = None`）现读注册表，
开关跟着注册表动；拨一下 → 写注册表 → 立刻作废缓存 → 下一帧重读，显示的是**真结果**。
`设置.txt` 里那份 `autostart` 只是「人的意图」，给整个文件夹搬到新机器时用。

三种状态：`开`（值 = 现在这个 exe）/ `未开` / **`指向旧位置`**（值在，但路径不是现在这个 exe，
多半是整个文件夹挪过地方）→ 面板多显示一行旧路径 + 一个「重写为当前位置」按钮。
写的是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，免管理员。

### 6.2 实测（真机 · 隔离副本 `lx_p3_check`）

| 动作 | 期望 | 实测 |
|---|---|---|
| 点开关（未开 → 开） | 注册表出现 `Lexideck`，路径 = 当前 exe | `REG_SZ "…\lx_p3_check\lexideck.exe"` ✓ |
| 外部把值改成 `C:\nope\lexideck.exe`，切页回来 | 显示「已开启，但指向的是旧位置」+ 重写按钮 | ✓ |
| 点「重写为当前位置」 | 值改回当前 exe | ✓ |
| 再点开关（开 → 未开） | 注册表那条消失 | `Lexideck: <none>` ✓ |
| 关掉程序 | 不会自己把条目加回来 | 注册表仍是 `<none>` ✓ |

### 6.3 验证时踩到的坑（留给以后写测试用）

- **滚面板**：`mouse_event(MOUSEEVENTF_WHEEL)` 和真实拖拽都进不去（点击是能进的），
  改成直接 `PostMessageW(hwnd, WM_MOUSEWHEEL, delta<<16, (y<<16)|x)` 一次就通。
- 内容比屏幕长时，把隔离副本的 `window_h` 调成接近整屏高，能省掉滚动这一步。
- debug 版 exe 是控制台程序：用 `Start-Process` / `ProcessStartInfo` 起它会**继承调用方的管道**，
  终端工具等管道 EOF 就卡死；改用 WMI `Win32_Process.Create` 起进程。

## 9 收进托盘后任务栏按钮没摘（2026-10-02 真机反馈）

**现象**（慕言）：托盘模式下关掉面板，任务栏上的窗口按钮还在；右下角也看不到托盘图标。

**两条互不相干的根因**：

1. **任务栏按钮 —— 真 bug**。「收进托盘」只是把面板挪到 `(-32000,-32000)`（§2.1 的原因），
   窗口在 Win32 眼里仍是「可见」态；而 winit 给普通顶层窗口加了 `WS_EX_APPWINDOW`，
   这个样式等于「强制进任务栏」。实测面板扩展样式 `0x00040110`（APPWINDOW | WINDOWEDGE | ACCEPTFILES）。
   修法：收进托盘时置 `WS_EX_TOOLWINDOW`、清 `WS_EX_APPWINDOW`；唤回时反过来。
   改完必须 `SetWindowPos(.., SWP_FRAMECHANGED)`，否则 Explorer 不重新评估、按钮赖着不走。
   实现 = `window::set_taskbar_visible(hwnd, visible)`；位运算拆成纯函数
   `ex_style_for_taskbar`，单测覆盖「两位互斥 + 幂等 + 其它位不动」。
   **为什么不干脆隐藏窗口**：见 §2.1 —— 隐藏会让「新建浮窗」踩上 eframe 那条旁路直接崩。

2. **托盘图标 —— 不是 bug**。图标一直是建好的：进程里有 `tray-icon` 的隐藏窗口（类名
   `tray_icon_app`），日志也有 `[tray] 创建托盘：面板 hwnd = ...`（这行在 `build()` 成功之后才打）。
   真相是 Windows 11 默认把新图标收进右下角 `^` 折叠区，不进常驻区。
   所以这轮只改文案：状态栏与设置页的提示直接说「图标在右下角 ^ 折叠区」。

**验证**（真机 · 隔离副本 `lx_p3_check/lx_traydev`，脚本 `lx_tray_verify.ps1`，读真实窗口样式）：

| 步骤 | 扩展样式 | 位置 |
|---|---|---|
| 启动 | `0x40110` APPWINDOW | (60,360) |
| 发 `WM_CLOSE`（关闭拦截 → 收进托盘） | `0x190` TOOLWINDOW | (-32000,-32000) |
| 再启动一次（单实例唤回） | `0x40110` APPWINDOW | (60,360) |

唤回走的就是 §7 的单实例通道，顺带确认它和任务栏样式恢复不打架。

### 9.1 补一刀：卡片也一直挂在任务栏上（2026-10-02 二次实测发现）

拆「层级 / 穿透」时顺手把四种组合都跑了一遍真机样式，发现**面板和卡片全都是 `APPWINDOW`** ——
也就是说卡片一直在任务栏上留按钮，正是慕言最早那句「关了任务栏窗口还在」的另一半。

**根因比原先记的更彻底**：不是「`with_taskbar` 只在建窗口时生效」，而是
**eframe 0.36 根本没有实现 `ViewportBuilder::taskbar`** —— 在 `eframe-0.36.2/src/` 里搜
`taskbar` 一个都搜不到（`egui` 侧只有 builder 字段的定义）。所以 `float_viewport` /
`menu_viewport` 里那两句 `.with_taskbar(false)` 都是空操作，窗口一律拿到 winit 的默认位
（`WindowFlags::ON_TASKBAR` → `WS_EX_APPWINDOW`，见 winit `window_state.rs`）。

**修法**（`window::ensure_no_taskbar`）：卡片是 eframe 动态建的、内部拿不到句柄，所以按标题
`词卡 #{id}` 用 `FindWindowW` 找回句柄再改扩展样式。**故意不记「改过没有」**：卡片隐藏后重新
显示时窗口会被重建，记标记会漏掉新窗口；改成每帧一次廉价自查（`taskbar_visible` 读样式，
不对才写）。成本 = 每卡每帧两次 Win32 调用（≤16 张卡）。

**验证**（`lx_dump_windows.ps1`，读真实 `GWL_EXSTYLE`；四种组合各起一次隔离副本）：

| 层级 / 穿透 | 卡片扩展样式 | 卡片位 | 面板 |
|---|---|---|---|
| 置底 / 不穿透 | `0x00000190` | TOOLWINDOW（不在任务栏） | `APPWINDOW` |
| 置底 / 穿透 | `0x000801B0` | TRANSPARENT + TOOLWINDOW | `APPWINDOW` |
| 置顶 / 不穿透 | `0x00000198` | TOPMOST + TOOLWINDOW | `APPWINDOW` |
| 置顶 / 穿透 | `0x000801B8` | TOPMOST + TRANSPARENT + TOOLWINDOW | `APPWINDOW` |

四行放在一起正好证明了层级与穿透互不影响：TOPMOST 只跟层级变、TRANSPARENT 只跟穿透变；
面板保留 `APPWINDOW` 是对的（它本来就该在任务栏上）。

### 9.2 「是真的没有留在托盘」—— 一次瞬时失败就毁掉整轮（2026-10-02 第二次反馈）

**过程值得记，因为第一轮我判错了**。慕言说「是真的没有留在托盘」，我先前的解释是
「图标建好了，只是被 Win11 收进 `^` 折叠区」。他不认，于是这次去要硬证据：

| 探针 | 结果 |
|---|---|
| 进程里的窗口类名（`lx_allwins.ps1`） | 有 `tray_icon_app` —— **但这不能当证据**（见下） |
| 外壳答复（`Shell_NotifyIconGetRect`，uID 试 0~3） | 全部 `E_FAIL` —— 外壳不认这个图标 |
| 注册表 `NotifyIconSettings` | 他跑的 `target/release` 路径**没有条目**；其余 13 个 lexideck 路径都有 |
| 对照实验（`lx_tray_selftest.ps1`，.NET `NotifyIcon` 加一个图标） | 加完**当场**多出一条键；`GetRect` 对 uID=1 返回 S_OK、uID=0 返回 E_FAIL |

结论有两层：

1. **「`tray_icon_app` 窗口在」不能证明图标加成功** —— 那是 crate 建宿主窗口的产物，
   `NIM_ADD` 返回 FALSE 时窗口照样在。这条把第一轮判断带偏了。
2. **「新加图标必然生成一条注册表键」**（对照实验证明）⇒ 他的路径没有键 = **从没加成功**，
   确实不是「被折叠」。外壳的 `E_FAIL` 与之一致。

**根因**：`NIM_ADD` 会瞬时失败（同一个 exe，16:16 起的实例图标正常、16:26 起的实例没有），
而代码写的是「失败只写一句 status，不重试」，那句 status 又只在面板底部一闪而过 ——
于是一次瞬时失败 = 整轮没有图标，而托盘恰恰是唤回面板的唯一通道。

**改法**（`app.rs`）：记住尝试次数与下次重试时刻，前 5 次每 2 秒、之后每 60 秒补试，
成功即恢复；失败原因（crate 原文）写进状态栏并说明会自动重试。
纯函数 `LexideckApp::tray_retry_gap` 单测覆盖。

**没查清的**：为什么那一次 `NIM_ADD` 会失败（同时段用 .NET 对照实验是成功的，说明外壳当时
是好的）。已用「重试」把它变成非致命，并且在修复版里会把 crate 的报错原文显示出来 ——
下次再遇到就有直接线索了。

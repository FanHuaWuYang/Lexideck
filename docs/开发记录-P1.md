## 1 这一轮做完的事

| 能力 | 现在的行为 | 为什么这么定 |
|---|---|---|
| 数据落地 | 只有一个主库 `lexideck.json`（exe 同目录）。旧的 `词表.json` 只在主库不存在时读一次、自动升级，之后不再被引用 | 导入的语义是「并进主库」，导入源之后与程序无关。只有一个事实来源，才不会出现「改了文件却没生效」 |
| 词库字段 | 词头、变形、词性+释义（可多条）、同根词、短语、例句（英中）、备注；六块内容各自可单独关闭默认展示 | 关闭项只影响屏幕，内容仍在库里，面板展开还能看到 |
| 格式校验 | 一份文件**先整体校验再决定导入**：版本必须是 1、词条必须有词头、释义至少一条、日期必须是严格的年月日（补零、真实存在、起≤止）、隐藏项只认六个名字。不合格整份拒绝，并一次列出**全部**问题而不是报第一个就停 | 老师手改 JSON 出错时，要一次看全、改完再导，不要来回试 |
| 读取宽容 | `null` 一律当「没写」；BOM 与 GBK 编码都能读；设置文件坏一行、多一个未知键都忽略，绝不因此不启动 | 面向非技术用户，坏的传播范围要小 |
| 导入 | 解析 → 校验 → 分类（新增／重复并入／冲突）→ 逐条问冲突 → 提交。冲突四按钮：跳过／替换／剩下的都跳过／剩下的都替换 | 提交前主库完全不动；写盘失败＝这次导入没发生，不留半个状态 |
| 结果清单 | 导入后在面板底部说清：新增几条、并入几条、替换/跳过几条、展示时间新增与重复几条；**展示时间里引用了库里没有的词会点名** | 这类错最像「AI 生成词表」会犯的错，静默写进去等于埋雷（逐个弹窗留到 P2） |
| 词表管理 | 首字母排序、搜索、全部／未选／已选筛选、点方框勾选、点整行展开（展开后能看到被关掉的区块并标注）、右下角「立即展示」 | 面板里不提供改内容的功能，只做选择与展示，防止有人乱按 |
| 控制面板 | 四个板块：词表／卡片／策略／设置；自绘顶栏与窗口按钮；窗口窄了自动收起右侧说明列；控件高度按触摸加大（≥34） | 一体机是触摸屏，且面板本身要能缩放 |
| 桌面卡片 | 新增「同根词」「备注」两个区块；六块统一受关闭开关控制；平铺仍是右上角起、往下排、满列向左、放不下按顺序截断 | 平铺规则与版式是既有约定，不改 |
| 面板图标 | 从 PNG 位图改成**矢量绘制**（归一化坐标 + 线宽随尺寸缩放） | 128px 位图缩到 20px 必然糊；矢量在任何缩放与 DPI 下都清晰 |
| 可读性 | 三套主题的小字号弱灰字，对比度从 2.9～3.2 提到 4.6 以上 | 12px 的说明文字在教室投影上原本看不清 |

### 顺手修掉的交互缺陷

- 卡片板块、设置板块内容超出窗口高度时，**超出的部分画在窗口外**——看不到、滚不到、按钮也点不到（现在整块可滚动）
- 列表行与行之间那 3px 空白：画着行背景、看着属于行，点下去行和底栏都不响应（现在是完整热区）
- 退出二次确认武装一次后永久有效，此后点顶栏的 ✕ 直接退出（现在 5 秒有效）
- 标题文字顶到右侧按钮底下（文字大小／主题／卡片层级三处）；列表行的展开箭头在缺字字体下显示成方块
- 单张卡片比屏幕还高时，被硬塞进屏幕溢出、还把本来能显示的卡片挤掉（现在按顺序截断）

## 3 验证方式（分清实测与没验到的）

**实测**

- 单元与无头渲染测试 **33 个全过**：词库解析与校验（含 null 语义、空变形、空词条数组、去重）、
  合并去重、导入冲突的四条分支、未匹配展示时间的提示、设置读写往返、平铺与截断规则，
  以及面板四个板块 + 两种弹窗在离屏环境里**真画一遍**（不 panic 且确实产出绘图指令）。
- 界面：把程序真跑起来逐页截图核对（词表／卡片／策略／设置 + 桌面卡片）。
- 文字与图标的垂直对齐：抓图后**逐行扫像素**，比较「文字墨迹中心」与「图标方块中心」，
  偏移 0px（修前 15px）。
- 三套主题的对比度：按 WCAG 公式对每一层底色（卡片底／行底／悬停底）取最差值，全部 ≥4.6。

**没验到的（如实记）**

- 导入那一条完整的点击链路：点「导入词表…」→ 系统文件选择框 → 选文件 → 冲突弹窗 → 点替换。
  系统的文件选择框不属于本程序进程，自动化点击不可靠；逻辑层有单测、渲染层有无头测试兜着，
  真正的点通请人在真机上走一遍。
- 设置板块在最小窗口（720×460）下的逐屏目视；卡片板块在该尺寸下已实测不裁切。
- 目标机器（教室一体机）上的透明、置顶、触摸尺寸四项仍未实测——按既定计划留在交付前。

## 4 这一轮踩的坑（教训已写进 `rust-windows-desktop-gui` skill）

1. **构建产物写去了别处**：审查用的子 agent 在共用的终端里设过「编译输出目录」这个环境变量，
   它留在了会话里，此后每次「编译成功」的产物都写进了另一个临时目录，`target/debug` 里的 exe
   一直没更新 → 我拿**旧程序**验了一整轮截图（连界面都还是上一版），并据此得出过错误结论。
   固定动作：构建前确认该变量为空、构建后核对产物时间比源码新，再启动。
2. **两行文字不能直接放进会「吃掉整块高度」的竖向容器**：文字会贴着卡片顶边排，
   而旁边的图标方块是按整卡居中的 —— 看起来就是「文字被上移了」。
   正解是先量出两行字的真实行高，给文字块一个确定高度的盒子，让它作为整体参与居中。
3. **单测写临时文件要按进程号唯一化**：这台机器的临时目录是多进程共用的，写固定名字会撞上
   「拒绝访问」，表现为单测偶发失败。

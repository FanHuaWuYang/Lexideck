# 教室一体机「英语单词悬浮展示」工具：形态与技术路线调研

> 调研时间：2026-09-17
> 调研方式：网络检索核实（版本号、稳定状态、许可、依赖）+ **本机实测**（用 Rust 编译了一个真实探针程序，量了体积、查了依赖 DLL、跑了 14 个解析器单元测试）
> 凡是"容易过期"的事实（版本号、是否稳定、依赖什么 DLL），都在文中标注了来源；凡是我**没有**验证过的，都在第 7.4 节明确列出。

## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 做什么形态 | **无边框半透明置顶小窗**（显示内容）+ **控制面板**（同一程序内，可"展开/收起"两态）。默认右下角，可拖动，可一键隐藏 |
| 用什么框架 | **Rust + egui / eframe 0.36（glow/OpenGL 后端）**。不选 Tauri、不选 Slint、不选 iced、不选 windows-rs 裸写 |
| 怎么部署 | **绿色单 exe**，静态链接 VC 运行库（`+crt-static`）；词表和配置文件都放在 exe 同目录；不写 AppData、不写注册表、不联网 |
| 词表放哪 | **外部 TXT 为主**（老师用记事本直接改，不用重新编译），程序内置一份默认词表做兜底；JSON 作为"高级可选" |
| 数据格式 | **宽容 TXT**：一行一个词 / `字段: 内容` / 空行分隔。**任何一行写坏都只影响那一行，绝不让整份文件失效** |
| 内容形式 | 一套**统一字段集**（主体 + 音标/词性/释义/例句/例句翻译/语法/备注），**自动推断**是单词卡、短语还是句子；界面上的下拉只用来"筛选"，不用来"切换模式" |
| 第一版做什么 | 只做 4 个动作：上一条、下一条、字号加减、隐藏。其余全砍 |
| 最大的两个坑 | ① eframe 0.36 把 `App::update(ctx, frame)` 改成了 `App::ui(ui, frame)`，网上 99% 的教程和 AI 记忆都是旧写法（本机实测编译报错 E0407）② 默认编译出的 exe 依赖 `VCRUNTIME140.dll`，教室机器没装 VC++ 运行库会直接报错（本机用 dumpbin 实测确认） |

## 1. 场景与硬约束

软件的第一用户是**一位非技术的中小学英语老师**，运行环境是**教室触控一体机**。这个场景里"老师上手是否零成本"的权重高于"技术多优雅"。本节把约束逐条翻译成设计后果，后面所有取舍都以这张表为准。

| 约束 | 来源 | 设计后果 |
|---|---|---|
| 使用者是英语老师，不会用命令行、不懂 JSON | 用户澄清 | 零配置、免安装、双击即用；数据格式必须容错；错误提示必须是中文人话 |
| 屏幕是**触摸屏**，老师用手指点 | 用户补充 | 按钮 ≥ 48pt（Google 无障碍建议 48dp≈9mm）[^g-touch]；不要右键菜单、不要悬停提示、不要快捷键当主路径；"上一条/下一条"必须能直接点 |
| 一体机常**不联网** | 用户补充 | 不能有"首次运行下载模型/字体/资源"的行为；所有资源内置或从系统取 |
| 可能装不了软件、受限账户、重启还原 | 用户补充 | 绿色单 exe；配置和词表放 exe 同目录；不写 AppData/注册表；写文件失败要静默降级 |
| 老师随时切到 PPT / 视频 / 直播 | 用户补充 | 必须能一键隐藏/呼出；且**绝不能挡住 PPT 的翻页点击** |
| 高频切换内容 | 用户补充 | 面板要有大按钮的上一条/下一条；可选自动轮播 |
| 高分屏（1920×1080 / 4K），不能变蚂蚁字 | 用户补充 | 跟随系统 DPI 自动缩放 + 手动字号调节 |
| 音响可能被占用 | 用户补充 | 不用声音提示，所有反馈靠画面 |
| 开发者在学 Rust，只有几天假期 | 用户背景 | 选"几天能出第一版"的框架；API 少而稳；避开需要写大量平台代码的方案 |

补充说明：**这套软件的目标不是"替代背单词 App"**，而是"老师在课堂上向全班展示，作为课前热身或讲某词/某句时的打断点"。所以它的核心指标是：*从老师坐下到屏幕上出现内容，不超过 15 秒；出错时屏幕上也必须有东西。*

## 2. Rust GUI 框架选型

### 2.1 候选现状（2026-09 逐条查证）

以下版本号均于 2026-09-17 查询 crates.io API（`https://crates.io/api/v1/crates/<名字>`）与 docs.rs 得到：

### 2.3 关键坑（实测记录，务必先知道）

**坑 1：eframe 0.36 的 `App` trait 变了。**

所有网上教程（以及大模型记忆）都是这么写的：

```rust
impl eframe::App for MyApp {
    fn update(&mut self, ctx: &egui::Context, frame: &mut eframe::Frame) { ... }
}
```

在 0.36.2 上编译会直接报错（本机实测）：

```
error[E0407]: method `update` is not a member of trait `eframe::App`
error[E0046]: not all trait items implemented, missing: `ui`
    = help: implement the missing item: `fn ui(&mut self, _: &mut Ui, _: &mut eframe::Frame)`
```

正确写法（docs.rs 上 `eframe::App` 的必需方法[^eframe-app]）：

```rust
impl eframe::App for MyApp {
    // 每个窗口需要重绘时调用；参数是 &mut Ui，不是 &Context
    fn ui(&mut self, ui: &mut egui::Ui, _frame: &mut eframe::Frame) {
        let ctx = ui.ctx().clone();       // 需要 Context 就从 ui 里拿
        ...
    }
    // 可选的额外钩子：
    // fn logic(&mut self, ctx: &egui::Context, frame: &mut eframe::Frame)  // 隐藏时也会被调用
    // fn clear_color(&self, _visuals: &egui::Visuals) -> [f32; 4]
}
```

顺带一提：`CentralPanel::show()` 在 0.36 里参数也变成了 `&mut Ui`（实测报错提示 `expected &mut Ui, found &Context`），所以别照抄老代码，直接用 `egui::Frame::NONE.show(ui, |ui| {...})` 或自己 `ui.painter().rect_filled(...)` 画背景最省事。

**坑 2：egui 默认字体不含中文。** 界面上的中文会显示成豆腐块。解决方式有两种：

- 读系统字体（推荐，exe 不膨胀）。Windows 一定有 `C:\Windows\Fonts\msyh.ttc`（微软雅黑），egui 的 `FontData` 带 `index` 字段支持 `.ttc` 字体集合[^egui-fontdata]：

```rust
fn cjk_font() -> Option<egui::FontData> {
    for (p, idx) in [("C:\\Windows\\Fonts\\msyh.ttc", 0u32),
                     ("C:\\Windows\\Fonts\\msyh.ttf", 0),
                     ("C:\\Windows\\Fonts\\simhei.ttf", 0),
                     ("C:\\Windows\\Fonts\\simsun.ttc", 0)] {
        if let Ok(b) = std::fs::read(p) {
            let mut fd = egui::FontData::from_owned(b);
            fd.index = idx;
            return Some(fd);
        }
    }
    None
}

let mut fonts = egui::FontDefinitions::default();
if let Some(fd) = cjk_font() {
    fonts.font_data.insert("cjk".into(), fd.into());
    fonts.families.get_mut(&egui::FontFamily::Proportional).unwrap()
        .insert(0, "cjk".into());   // 插到最前面，优先用中文
    cc.egui_ctx.set_fonts(fonts);
}
```

  四级回退（雅黑 → 雅黑 ttf → 黑体 → 宋体）保证任何一台 Windows 都能拿到字体；万一都失败，至少英文还能显示，不会崩。
- 或者把字体文件 `include_bytes!` 编进 exe。**不推荐**：一个完整中文字体 10–20 MB，会让 exe 从 5 MB 膨胀到 20+ MB，而收益只是"防系统字体缺失"（这在 Windows 上几乎不可能发生）。

**坑 3：别用 eframe 自带的"持久化"功能。** `eframe::storage_dir()` 的路径是 `C:\Users\<用户名>\AppData\Roaming\<APP_ID>\data`[^eframe-storage]。教室机器一重启就还原，配置等于没存。**自己在 exe 同目录写文件**：

```rust
let dir = std::env::current_exe().ok()
    .and_then(|p| p.parent().map(|p| p.to_path_buf()))
    .unwrap_or_else(|| std::path::PathBuf::from("."));
// 配置写 dir.join("设置.txt")，词表读 dir.join("词表.txt")
```

**坑 4（重要）：渲染后端选 glow，不要选 wgpu。** eframe 从 0.34 起把默认渲染后端从 glow（OpenGL）换成了 wgpu[^survey2026]。wgpu 在 Windows 上默认走 DX12/Vulkan，对教室一体机那种老核显 + 老驱动不太友好。选 glow（OpenGL 2.1 级）兼容性明显更宽。本机实测编译出来的 exe 依赖 `OPENGL32.dll / GDI32.dll / dwmapi.dll`，没有任何 D3D12/Vulkan 相关依赖（dumpbin 结果见 4.1），这正是我们要的。

### 2.4 取舍结论

**主选：`eframe` 0.36 + `glow` 后端 + 手写一个极简组件（不用第三方主题库）。**

理由，按权重排序：

1. **只有它把"无边框 + 透明 + 置顶 + 拖拽 + **运行时可切换的鼠标穿透**"全都做成了现成 API**（`ViewportBuilder` 与 `ViewportCommand`）。穿透运行时可切换这一条是关键：Slint / iced / Tauri 都没有，都要自己写 Win32 代码——那正好是 Rust 新手最不该碰的部分。本机已实测这些 API 在 0.36.2 上存在且可编译可运行。
2. **立即模式对新手最友好**：UI 就是一串顺序函数调用，没有"状态和界面不同步"的坑，也不需要理解 Elm 架构或 DSL。一份 2026 年的横向评测也提到 egui 是"最没有明显摩擦"的两个之一[^survey2026]。
3. **产物小、无运行时依赖**（5 MB 单 exe，见第 4 节），完美契合"拷 U 盘就能跑"。
4. 中文虽然要手动加字体，但代码只有 10 行（见坑 2），一次性成本。

**备选：Slint**——它的 API 稳定性是 egui 比不了的，而且中文直接走系统字体。但它缺三样东西：内置透明窗口属性（要在 `Window` 上手写 Win32）、内置鼠标穿透、以及**免版税许可要求公开声明使用 Slint**[^slint-license]（对一个自己用的小工具无所谓，但要知道）。如果哪天你觉得 egui 版本升级太烦、愿意自己处理这三件事，Slint 是唯一值得换的目标。

**明确不选：**

- **Tauri**：为了一个 5 MB 的小挂件引入"必须装 WebView2 运行时"这个前置条件（见 4.3），在教室一体机上这是不可接受的失败模式；而且它还要 HTML/CSS/JS 或额外工具链，对学 Rust 没有帮助。
- **iced**：架构优雅、但无障碍缺失、文档可发现性差[^survey2026]，而且悬浮窗那三项要自己补，性价比低。
- **windows-rs 裸写**：体积最小、控制最彻底，但要自己处理窗口类注册、消息循环、DPI、渲染、输入、文本排版——**这不是几天能完成的项目**，也不适合当作学 Rust 的第一个 GUI 项目。
- **Floem / Freya / gpui**：2026 年评测里分别败在"IME 完全不工作 / 无障碍不可用 / 连文本输入控件都没有，还 panic"[^survey2026]。不要碰。
- **Azul / Maycoon / Pane UI / Pax 之类**：评测中直接是"读不到字体 / 已废弃 / 加载不了图片 / 编译失败"[^survey2026]。不要碰。

**一个务实的替代路线（如果 egui 折腾不动）**：直接写一个**本地 HTML 文件 + 浏览器窗口**。理由：老师机器上一定有浏览器，HTML/CSS 做半透明圆角卡片是几分钟的事，数据用 `<script>` 读不了本地文件（file:// 的 fetch 受限），可以把词表转成 JS 变量内嵌。代价是：不能真置顶（浏览器窗口会被 PPT 盖住）、不能鼠标穿透、不能鼠标拖拽外框。**所以它只能当"最后的 B 计划"，不能当主路线**——本项目的核心诉求恰好是浏览器做不到的那三条。

## 3. 悬浮窗的四种形态对比

### 3.1 四种做法

| 形态 | 说明 | 优点 | 缺点 | 适配本场景 |
|---|---|---|---|---|
| **A. 普通无边框窗口 + 置顶** | 一个 `WS_EX_TOPMOST` 的普通窗口，自己画圆角背景 | 实现最简单；能接收点击；能拖拽；能调整大小 | 会盖住它所在矩形内的 PPT 内容；关掉程序才会消失 | ⭐ 推荐的基础形态 |
| **B. 贴在桌面层的挂件（wallpaper layer）** | 把窗口挂到 `WorkerW` 下，与壁纸同层 | 永不挡任何程序 | **PPT 一全屏就被盖住**——而老师恰恰要开着 PPT 看单词 | ❌ 直接出局 |
| **C. 系统托盘 + 按需呼出** | 平时只在托盘，按快捷键/点图标才弹 | 最不打扰；老师切 PPT 时它根本不在 | 触摸屏上点托盘小图标很难；必须配合快捷键 | ⭐ 作为 A 的补充（隐藏方式） |
| **D. 全屏半透明覆盖层** | 铺满全屏、鼠标穿透、只在上方画字 | 视觉最"高级"，字可以被安排到任何位置 | 全屏半透明会让 PPT 整体变灰，色彩和对比度全毁；对课堂展示是负分 | ❌ 出局 |

**结论：A 为主体，C 为补充，B 和 D 不要做。** 一句话理由是：这个工具的展示对象是**全班学生看投影**，字要让后排看得清，而挂件层会被 PPT 盖住、全屏覆盖层会把 PPT 弄脏。

### 3.2 怎么保证"绝不挡住 PPT 翻页"

这是本项目的硬需求。分成四层防御，从最省事到最彻底：

**第 1 层：位置与尺寸。** 默认放在**右下角**（Windows 通知区域上方，避开 PPT 母版常用的页脚标题区），默认尺寸约 `620 × 300` 逻辑点，可拖动。老师把 PPT 翻页区域（整个屏幕）中的这一小块让出来即可——PPT 的点击翻页只在**鼠标点在 PPT 窗口内**时生效，只要点不到悬浮窗，翻页就不受影响。

**第 2 层：一键隐藏。** 三种入口，覆盖不同习惯：

- 全局快捷键 `Ctrl+Alt+H`（**强烈建议只保留这一个快捷键**，多了老师记不住）
- 面板上的大按钮"隐藏"（在穿透模式关闭时用）
- 系统托盘图标菜单（触摸屏上不好点，仅作兜底）

**第 3 层：鼠标穿透（最彻底）。** 开启后整个窗口变成"透明玻璃"，所有点击都穿到底下的 PPT。实现方式见 3.3。

**第 4 层：不抢焦点。** 窗口显示时不要抢走 PPT 的键盘焦点（否则老师按空格翻页可能失效）。egui 的 `ViewportBuilder` 有 `active` 字段可以控制初始是否激活[^egui-viewport]。原则：**我们的窗口永远不需要键盘焦点**——它只用触摸/鼠标点击。

⚠️ **穿透的陷阱**：一旦开了穿透，鼠标就点不到面板上的任何按钮了，**只能靠全局快捷键切回来**。所以：

- `Ctrl+Alt+P` 必须是"切换穿透"的快捷键，且必须有；
- 或者更稳妥：**默认不开穿透**，把穿透做成"临时 30 秒"（老师点一下"让一下"，30 秒后自动恢复可点）；
- 第一版建议：**先不做穿透**，只做"隐藏/显示"，就已经能解决 95% 的遮挡问题。

### 3.3 鼠标穿透的具体做法（Rust）

**推荐做法：用 egui/eframe 现成的 API，不要自己写 Win32。**

```rust
use egui::viewport::ViewportCommand;

// 打开穿透：鼠标事件全部交给下面的窗口
ctx.send_viewport_command(ViewportCommand::MousePassthrough(true));
// 关闭穿透
ctx.send_viewport_command(ViewportCommand::MousePassthrough(false));
```

依据：egui 0.36.2 的 `ViewportCommand` 枚举里确实有 `MousePassthrough(bool)`，文档描述为"鼠标点击穿过窗口，用于不可交互的覆盖层"[^egui-viewport]。它底层走的是 winit 的 `Window::set_cursor_hittest(false)`[^winit-docs]，而 winit 在 Windows 平台上的实现是（源码 v0.30.13 实测查阅）：
```rust
// winit/src/platform_impl/windows/window_state.rs
if self.contains(WindowFlags::IGNORE_CURSOR_EVENT) {
    style_ex |= WS_EX_TRANSPARENT | WS_EX_LAYERED;
}
```

也就是说 winit 帮我们把 `WS_EX_TRANSPARENT | WS_EX_LAYERED` 设好了，这正是 Windows 上实现点击穿透的标准做法[^so-clickthrough]。**本机实测：`MousePassthrough` 可以在运行时反复 ON→OFF→ON→OFF 切换四次，窗口不消失、不 panic、几何尺寸不变**（详见附录 B）。注意 winit 的 `set_cursor_hittest` 文档明确说这只是给系统的一个 hint，系统可能忽略[^winit-docs]，所以"点击是否真的穿过去"要在真实一体机上验一次。

**如果你坚持自己写 Win32（不推荐，仅在发现 egui 的封装不满足需求时）：**

```rust
use windows::Win32::Foundation::HWND;
use windows::Win32::UI::WindowsAndMessaging::{
    GetWindowLongPtrW, SetWindowLongPtrW, GWL_EXSTYLE,
    WS_EX_LAYERED, WS_EX_TRANSPARENT, WS_EX_TOOLWINDOW,
};

unsafe fn set_click_through(hwnd: HWND, on: bool) {
    let mut ex = GetWindowLongPtrW(hwnd, GWL_EXSTYLE);
    if on {
        ex |= (WS_EX_LAYERED | WS_EX_TRANSPARENT) as isize;
    } else {
        // 只清掉穿透位，保留 LAYERED，否则窗口可能失去逐像素透明能力
        ex &= !(WS_EX_TRANSPARENT as isize);
    }
    SetWindowLongPtrW(hwnd, GWL_EXSTYLE, ex);
}
```

三个必须知道的坑：

1. **`WS_EX_TRANSPARENT` 和 `WS_EX_LAYERED` 要一起设**，只设前者不生效[^so-clickthrough]。
2. **关闭穿透时不要连 `WS_EX_LAYERED` 一起清掉**，否则半透明背景会变成不透明黑块（如果透明度是你自己用 `SetLayeredWindowAttributes` 做的）。用 winit/egui 封装则没有这个问题——winit 的透明度不走 `WS_EX_LAYERED`（它的 `TRANSPARENT` 标志位不映射到 LAYERED），两者互不干扰[^winit-src]。
3. 拿 `hwnd` 的方式：eframe 里可以从 `frame` 拿到原生句柄（`raw_window_handle`），比"用窗口标题 `FindWindowW` 找自己的窗口"稳得多——后者在窗口标题含中文时容易踩字符集的坑。

**结论：优先用 `ViewportCommand::MousePassthrough`，只有在实测发现问题时才退到手写 Win32。**

### 3.4 触摸屏的 UI 要求（一体机专属）

老师大概率**用手指直接点，不用鼠标键盘**。这带来几条硬性 UI 规则：

| 规则 | 具体值 | 依据 |
|---|---|---|
| 最小触摸目标 | **48×48 dp（约 9 mm）**，相邻目标间隔 ≥ 8 dp | Google 无障碍指南[^g-touch] |
| 我们的实际取值 | 主按钮 **64×64 逻辑点**，上一条/下一条 **≥ 72×72**，字号加减 64×64 | 留 30%+ 余量，避免一体机触控校准偏差 |
| 禁止依赖悬停 | 不用 tooltip、不用 hover 变色作为唯一反馈 | 触摸屏没有 hover |
| 禁止依赖右键 | 不用右键菜单；所有操作都要有可见按钮 | 触摸长按右键体验差 |
| 按钮文字 | 用**图形符号 + 中文大字**（"◀ 上一个" / "下一个 ▶"），不要只放一个小图标 | 老师一眼看懂 |
| 点击反馈 | 按下即变色（egui 的 `Button` 默认就有） | 触摸时有"点到了"的确认感 |
| 面板排布 | 高频操作（上一条/下一条/字号）放**最上一行**，一行不超过 5 个按钮 | 拇指够得着，不用精确瞄准 |
| 关闭按钮 | **不要放"退出"**，只放"隐藏"。老师上课误关程序是灾难 | 退出藏到托盘菜单里 |

一个容易被忽略的点：**一体机上的托盘图标很难点**（要先唤出任务栏、再点小图标）。所以"隐藏/呼出"的主入口应该是**全局快捷键 + 面板大按钮**，托盘只作为兜底。而"下一个/上一个"在主窗口上直接点，不依赖快捷键。

**另一个可能的彩蛋**：很多教室在用**翻页笔（演示遥控器）**，它一般模拟 `PageUp/PageDown` 或方向键。可以（第二版）加一个选项："当悬浮窗是活动窗口时，用方向键翻词"。注意**不要**把方向键注册成全局快捷键——那会和 PPT 抢翻页。

### 3.5 高分屏（1080p / 4K）

- egui 用"逻辑点"坐标系，会根据 winit 报告的缩放系数自动换算物理像素[^egui-dpi]，所以系统缩放 200% 时按钮会等比放大，**不会变成蚂蚁字**。
- 两个要自己处理的情况：
  1. **4K 屏但系统缩放被设成了 100%**（一体机常见误配）→ 默认字号会偏小。对策：面板里给 **A- / A+**，以及一个"界面缩放"（直接改 `ctx.set_zoom_factor()` 或自己乘一个系数）。字号范围建议 0.8×–3.0×。
  2. **多屏**（教室电脑接了投影时可能有两块屏）→ 窗口默认出现在主屏；给一个"移到另一块屏"按钮或让老师直接拖过去。
- 不要硬编码像素尺寸，所有尺寸用逻辑点写。

## 4. 免安装绿色单 exe 的可行性

**结论：完全可行，而且这是本项目最省心的部分。** 但有两个必须处理的细节，否则会出现"在你自己电脑上好用，拷到教室就打不开"。

### 4.1 本机实测数据（2026-09-17，Windows 11 + rustc 1.97.1 + MSVC 14.51）

我用一个真实探针程序（无边框 + 透明 + 置顶 + 拖拽 + 中文字体 + 宽容词表解析器）实测：

**编译配置：**

```toml
# Cargo.toml
[dependencies]
eframe = { version = "0.36", default-features = false, features = ["glow", "default_fonts"] }
encoding_rs = "0.8"

[profile.release]
opt-level = 3
lto = true
codegen-units = 1
panic = "abort"
strip = true
```

```toml
# .cargo/config.toml
[target.'cfg(all(windows, target_env = "msvc"))']
rustflags = ["-C", "target-feature=+crt-static"]
```

**产物与依赖（dumpbin /dependents 实测）：**

| 配置 | exe 体积 | 外部 DLL 依赖 |
|---|---|---|
| 默认（不加 `+crt-static`） | **5,464,576 字节（5.21 MiB）** | `kernel32 user32 ole32 ntdll shell32 bcryptprimitives OPENGL32 GDI32 ADVAPI32 imm32 dwmapi uxtheme` + **`VCRUNTIME140.dll`** + 一批 `api-ms-win-crt-*.dll` |
| 加 `+crt-static`（推荐） | **5,642,240 字节（5.38 MiB）**，只多了 **174 KB** | **`VCRUNTIME140.dll` 与 `api-ms-win-crt-*.dll` 全部消失**，只剩系统自带 DLL：`kernel32 user32 ole32 ntdll shell32 api-ms-win-core-synch-l1-2-0 bcryptprimitives OPENGL32 GDI32 ADVAPI32 imm32 dwmapi uxtheme` |

也就是说：**多花 174 KB，换来"绝不出现找不到 VCRUNTIME140.dll"**——这笔买卖非常划算，建议无条件加上。

要点解释：

- **`api-ms-win-crt-*.dll` 不用管**：这些是 Universal CRT，是 Windows 10 及以上系统自带的组件，不是需要分发的文件[^static-vcruntime]。
- **`VCRUNTIME140.dll` 必须管**：它属于 VC++ 2015–2022 运行库，**不是** Windows 自带。教室机器如果没装过 VC++ 运行库，程序会直接弹"由于找不到 VCRUNTIME140.dll，无法继续执行代码"[^ms-vcruntime]。
- `dwmapi.dll` + `OPENGL32.dll` 的存在说明透明效果走的是 DWM 合成（Windows Vista 后的标准做法），没有 D3D12/Vulkan 依赖——这对老核显友好。
- 5 MB 里绝大部分是 egui/winit 的代码和字体图集；`lto + codegen-units=1 + panic=abort + strip` 已经把能省的都省了。**不要追求极致缩小体积**（比如 `opt-level="z"`），那会牺牲绘制性能，而教室一体机性能本身就紧张。

**关于 `+crt-static` 的两种做法：**

1. **直接 `-C target-feature=+crt-static`**（上面推荐的做法）：把 C 启动代码、VC 运行库、Universal CRT 全部静态链接。副作用是 exe 变大几十~几百 KB。Rust 官方 RFC 就是这么设计的[^rfc1721]。
2. **`static_vcruntime` crate**（v3.0.0，2025-11-25）：只静态链接 VC 运行库，UCRT 仍走系统动态链接，体积更省。作者也建议**同时**加上 `+crt-static` 以获得最好的兼容性[^static-vcruntime]。适合哪天你觉得 exe 大得难受时再换。

⚠️ 需要注意的坑：`+crt-static` 是**全局 rustflags**，一加就会让所有依赖全部重新编译（我第一次增量编译花了 ~9 分钟）。而且如果哪天加了需要动态 CRT 的 C 依赖（比如某些 FFI 库），可能会撞链接错误。**建议一开始就加上，别等最后再加。**

### 4.2 为什么 Tauri 会更"重"

- Tauri 不自绘界面，它用**系统 WebView2** 渲染 HTML。产出的 exe 确实小（教程里常提"hello world ~3 MB"[^tauri-size]），但**前提是目标机器上装了 WebView2 运行时**。
- WebView2 在 Windows 11 上预装，在 Windows 10 上通常随 Edge 一起装上——**但教室一体机不一定**：很多是 Win7/Win8.1 或长期不更新的 Win10 LTSC。
- 而且 **Microsoft 已经在 2022-12-09 宣布 Edge 和 WebView2 停止支持 Windows 7 / 8 / 8.1，最终版本停在 109**[^ms-edge-eol]。也就是说老一体机上你连"让老师装一下"这条路都走不通。
- 想彻底摆脱这个依赖，Tauri 提供"嵌入固定版本 WebView2"的选项，但官方文档明说**这会让安装包增大约 180 MB**[^tauri-fixed]——完全违背"绿色小工具"的初衷。
- 反过来看 egui：一个 exe 自带全部渲染逻辑，**没有任何运行时前置条件**。这就是选 egui 而不是 Tauri 的决定性理由。

### 4.3 杀毒软件误报的可能性

- **确有可能，但概率不高、且可控。** Rust 编译出的、无签名的、体积不大、行为"可疑"（读取键盘全局快捷键、修改窗口样式、写文件到自身目录）的 exe，偶尔会被 Windows Defender 或其他杀软报成木马（社区里 `Trojan:Win32/…!ml` 这类误报是已知现象[^rust-fp]）。"!ml" 结尾的一般是机器学习启发式误报。
- 缓解手段（按性价比排序）：
  1. **不要加壳、不要用 UPX 压缩**——那是最容易触发误报的操作，而且和 `strip` 的效果重叠。
  2. **不要在程序里做"看起来像恶意软件"的事**：不要开机自启（写注册表 Run 项）、不要隐藏窗口启动、不要读写别的进程。我们只需要"全局快捷键 + 悬浮窗"，这已经足够温和。
  3. 如果真被误报：把 exe 提交给微软 `https://www.microsoft.com/en-us/wdsi/filesubmission` 申诉，或者在一体机上把该文件加到 Defender 排除项（需要管理员权限，可能做不到）。
  4. **最实际的办法**：在一体机上先试一次。如果被拦，退路是"用记事本/浏览器方案"或者"让学校网管加白名单"。
- 全局快捷键这个功能本身**不**需要管理员权限，不涉及驱动，属于正常应用行为，不是主要误报来源。

### 4.4 受限账户 / 重启还原的应对

| 风险 | 事实 | 应对 |
|---|---|---|
| 写不进 `Program Files` | 受限账户对 `Program Files`、`C:\Windows` 无写权限 | exe 放**桌面**或 **U 盘**，配置和词表放 exe 同目录 |
| 写不进 exe 同目录 | 若 exe 放在 `Program Files` 或只读介质（光盘、写保护 U 盘），`std::fs::write` 会失败 | **所有写操作都要 `let _ =` 忽略错误**，失败就只在内存里生效，绝不弹错误框、绝不崩 |
| 重启还原 | 桌面的东西可能被还原 | 词表源文件**同时在 U 盘留一份**；程序不需要常驻，老师上课前双击即可 |
| 装不了软件 | 不需要安装 | 绿色 exe，无注册表、无服务、无驱动、无开机自启 |
| 不能联网 | 无网络依赖 | 所有资源内置/取系统字体；不发起任何网络请求 |

**唯一必须"常驻"的功能是全局快捷键**（用来一键隐藏）。这需要程序在后台运行：最小化到托盘/隐藏主窗口即可，无需系统服务。如果不想要常驻，退而求其次的方案是：不做全局快捷键，只靠面板上的"隐藏"按钮——但那意味着穿透模式下无法自救，所以**第一版先把穿透砍掉**，就没有这个问题。

### 4.5 推荐编译配置（可直接抄）

```toml

[package]
name = "word-float"
version = "0.1.0"
edition = "2021"

[dependencies]
eframe = { version = "0.36", default-features = false, features = ["glow", "default_fonts"] }

serde = { version = "1", features = ["derive"] }   # 可选：读写 settings.json

```


**关键提醒：显式写 `default-features = false, features = ["glow", "default_fonts"]`。** eframe 的默认特性里包含 `wayland`、`x11`、`accesskit`、`wgpu`——在 Windows 上 x11/wayland 是死重量，wgpu 是老硬件的兼容性风险，accesskit 我们也不需要（无障碍 API 会常驻后台）。关掉它们，编译更快、体积更小、跑起来更稳。

```bash

# 产物：target/release/word-float.exe   → 拷到 U 盘即可
```


## 5. 词表存储与切换

### 5.1 内嵌 vs 外部 vs 混合

| 方案 | 老师改词表要重新编译吗 | U 盘拷来拷去方便吗 | 结论 |
|---|---|---|---|
| **全部内嵌**（`include_str!`） | **要**（老师不可能做） | 只能整包换 exe | ❌ 不可用 |
| **全部外部**（同目录 txt/json） | 不要，记事本改完即生效 | 要连同文件夹一起拷（容易漏） | ⭐ 主方案 |
| **混合（内嵌默认 + 外部覆盖）** | 不要 | 只拷 exe 也能跑（用内置词表）；想换内容时再带一个 txt | ⭐⭐ **推荐** |

**推荐混合方案的具体规则（按优先级顺序找）：**

1. exe 同目录的 `词表.txt`
2. exe 同目录的 `词表/` 子目录下**所有** `.txt` / `.json`（按文件名排序，面板上可切换）
3. 都没有 → 用编译进 exe 的默认词表（`include_str!("../default_words.txt")`），并在面板上提示"当前使用内置词表，把你的词表放在程序旁边即可"

这样做的价值：**程序永远不会"打开是空的"**。对非技术用户来说，"打开有东西看"比"提示我没找到文件"重要得多。

`include_str!` 的默认词表建议放 20–50 个高频词 + 2 个句子，让老师第一次打开就能看懂格式，直接模仿着改。

### 5.2 格式对比：JSON 还是 TXT？（面向非技术用户）

先看一个真实的差别。老师想加一个词，两种格式分别要打成什么样：

**JSON（严格语法）**

```json
[
  {
    "word": "abandon",
    "phonetic": "/əˈbændən/",
    "pos": "v.",
    "meaning": "抛弃，放弃"
  }
]
```

老师可能犯的错，以及后果：

| 错误 | 后果 |
|---|---|
| 少一个逗号 | **整份文件解析失败，一个字都显示不出来** |
| 键名打成 `"Word"` 或 `"单词"` | 该字段静默丢失（除非程序专门做了大小写/别名兼容） |
| 用了中文引号 `“abandon”` | 整份文件解析失败 |
| 多了一个尾随逗号 | 整份文件解析失败 |
| 用记事本另存为时带了 BOM | 有些解析器会因此直接报错，而且是英文的 `expected value at line 1 column 1`[^serde-err]（老师完全看不懂） |
| 双引号被 Word 自动变成弯引号（老师在 Word 里编辑再导出） | 整份文件解析失败 |

**TXT（宽松格式，本方案）**

```
abandon
音标: /əˈbændən/
词性: v.
释义: 抛弃，放弃

benefit
释义: 受益
```

老师可能犯的错，以及后果：

| 错误 | 后果 |
|---|---|
| 少写冒号（`音标 /əˈbændən/`） | 仍然被正确识别为音标（见下文"宽容规则"） |
| 键名写错（`中文名: 抛弃`） | 这一行**原样显示在单词下方**，不丢内容、不影响其他行 |
| 空行太多/太少 | 无影响 |
| 文件里有说明文字 | 显示出来而已 |
| 一行就是一个词（完全不写字段） | 完美工作，一行一个单词卡 |

**JSON 和 TXT 的核心区别不是"表达能力强弱"，而是"错误的传播范围"**：

- JSON 的错误是**全局的**（一个逗号 → 全文件失效）；
- 宽松 TXT 的错误是**局部的**（一行写坏 → 只有那一行退化）。

对"非技术老师 + 上课现场"这个组合，这个差别就是"能不能用"的差别。

**辅助因素：**

- **文件关联**：`.txt` 双击一定用记事本打开，行为可预期；`.json` 在 Windows 上的默认关联**不统一**——Windows 11 上常关联到记事本，但也有很多机器上**没有默认程序**或关联到浏览器[^json-assoc]。老师双击 `.json` 打开浏览器或弹出"选择应用"对话框，就足够让他放弃了。
- **CSV**：看似像表格，实则陷阱更多——只要内容里有逗号（中文释义里太常见了："抛弃，放弃"）就必须加引号，Excel 另存又可能改变编码和引号规则，还会把 `1-2` 之类自动转成日期。**不推荐**。
- **TOML**：对程序员友好，但对老师来说"为什么有的值要引号、有的不要"是无法理解的[^toml]。**不推荐作为面向老师的格式**。
- **YAML**：靠缩进表达层级，缩进错了就解析失败，而且报错信息对非技术用户完全不可读。**绝对不要给老师用。**
- **Markdown**：作为"纯文本"它和 TXT 一样安全，但老师不会因为多几个 `#` 就更好过，反而容易把 `**加粗**` 当成内容。**没必要**。

**结论：主推 TXT（宽松格式），同时支持 JSON 作为"高级可选格式"。**

JSON 的定位要说清楚：**它是给"以后有人帮你生成词表"准备的**——比如从 Excel 批量导出、从某个词库网站抓下来，程序自动写一个 JSON 文件，比写 TXT 更不容易出错。所以程序要能读 JSON，但**不要求老师手写 JSON**。程序在文件格式错误时，应当退回按 TXT 逐行解析（见 5.4），这样即使老师手抖改坏了 JSON，屏幕上依然会有东西。

### 5.3 编码：一个中国教室里真实的坑

- Windows 10 1903 之后，**记事本的默认保存编码是 UTF-8（不带 BOM）**[^notepad-utf8]。
- **但**：机器上可能装着 WPS、或者老师用的是老版本系统/老版本编辑器，仍然可能产出 **GBK/ANSI** 文件。
- 如果程序只按 UTF-8 读，GBK 文件里的中文会变成乱码。

**处理方式（本机已实测通过）：**

```rust
fn read_text_any_encoding(path: &Path) -> Option<String> {
    let bytes = std::fs::read(path).ok()?;
    // 1) 带 BOM 的 UTF-8
    if bytes.starts_with(&[0xEF, 0xBB, 0xBF]) {
        return String::from_utf8(bytes[3..].to_vec()).ok();
    }
    // 2) 纯 UTF-8
    if let Ok(s) = std::str::from_utf8(&bytes) {
        return Some(s.to_string());
    }
    // 3) 都不是 → 按 GB18030 解（兼容 GBK/GB2312）
    let (cow, _, _) = encoding_rs::GB18030.decode(&bytes);
    Some(cow.into_owned())
}
```

依赖 `encoding_rs`（0.8.41，2026-09-09 查询 crates.io），是 Firefox 用的同一套实现，纯 Rust、无额外依赖、体积代价小。

**为什么这个顺序是对的**：UTF-8 是自校验格式，任何合法 UTF-8 文本都不会被误判成 GBK；反过来，GBK 文件几乎一定包含非法 UTF-8 字节序列。所以"先试 UTF-8、失败再当 GBK"是安全且几乎不会出错的。

### 5.4 出错时的优雅降级（这一节是整套设计的核心）

**总原则：屏幕上有东西 > 提示错误。老师在上课，没有时间处理报错。**

四层降级策略：

| 情况 | 程序行为（绝不只是打印错误） |
|---|---|
| 找不到词表文件 | 用内置默认词表 + 状态栏提示"当前使用内置词表" |
| 文件是空的 | 显示"这个词表还没有内容"，保持窗口可用 |
| 文件编码怪异 | GB18030 兜底解码，正常显示 |
| **某一行写坏了** | **跳过/降级显示那一行，其余照常**；状态栏出现一条黄色提示条 |
| 整份 JSON 解析失败 | 自动退回按宽松 TXT 逐行解析（JSON 的 `{ "a": "b" }` 在 TXT 解析器眼里就是普通文字，不会崩） |
| 修改后新内容解析不出东西 | **保留上一份能用的内容**，并提示"新内容好像有问题，仍显示旧内容" |
| 写配置文件失败（只读 U 盘等） | 静默忽略，仅内存生效 |

**提示文案怎么写（给老师看的）：**

不要写：

> `Err(Error { line: 12, column: 5 }): expected `,` or `}` at line 12 column 5`

要写：

> ⚠ 第 12 行好像写错了：「音标 /əˈbændə」这一行暂时没显示出来。
> 其他内容都正常。改好这一行后会自动更新。
> 提示：字段名后面直接跟内容就行，冒号可以不用写。

也就是：**给出行号 + 原样引用那一行 + 说明只影响这一行 + 给一条修复建议 + 告诉老师"其他都正常"**。`serde_json::Error` 提供 `line()` / `column()` 方法[^serde-err]，可以拿到行号；但即使拿不到行号，也要给出"文件里的第几段"这种近似定位。

**"最后一份好内容"机制（强烈建议做）：**

程序每次**成功**解析词表后，把解析结果（或规范化后的文本）另存一份到同目录（例如 `词表.上次正常.txt`）。下次启动或热更新失败时，优先拿这份来显示。这样老师任何误操作都不会让课堂黑屏。

**本机实测的解析器行为（14 个单元测试全部通过）**——完整可编译源码已保存到 `03_开发与测试/word-float-probe/src/parser.rs`：

```

test parser::tests::english_words_are_not_mistaken_for_keys ... ok  position/translation/phone 不会被误判成字段名 ✔
```

**宽容 TXT 的完整规则（4 条，老师只需要记住第 1 条）：**

1. **一行一个词 / 一句话** → 这是最简单、最不容易出错的用法。
2. **`字段名: 内容`**（冒号可写可不写，中英文冒号都行）→ 挂到上一条记录上。
3. **空行或 `---`** → 开始下一条记录。
4. **认不出的行** → 原样显示在那条记录下方，**不算错误、不会丢**。

程序自动做的一件贴心事：**如果一行以某个已知字段名开头，即使没写冒号，也当成那个字段**。但加了防误判规则——只有"字段名 + 空格/斜杠等非字母数字字符 + 内容"才算，所以 `position`、`translation`、`phone` 这些以 `pos`/`trans`/`ph` 开头的真实单词**不会**被误吃（这条已单测覆盖）。

### 5.5 词表切换与热更新

- **切换**：启动时扫描 exe 同目录 + `词表/` 子目录，面板上一个**大字号下拉框**列出所有 `.txt` / `.json`；选中即切换。老师也常把文件重命名成"Unit1.txt / Unit2.txt"——按文件名排序即可，符合直觉。
- **热更新（推荐做，成本极低）**：每 1–2 秒检查一次当前词表文件的修改时间（`metadata().modified()`），变了就重新解析。老师用记事本改完 `Ctrl+S`，2 秒后屏幕上就变了，**完全不需要点任何按钮**。这比引入 `notify` 文件监听库（最新稳定版 8.2.0[^crates-notify]）更简单也更好调试——轮询几毫秒的开销对课堂场景完全无感。
- **不建议**给老师"刷新"按钮作为主路径（要额外操作），但可以留一个"重新读取"按钮作为心理安慰。

## 6. 内容形式（单词卡 / 短语 / 句子）的数据结构

### 6.1 一套统一字段集（不设"模式"）

关键设计决定：**不给老师"选择内容形式"的概念**。只有**一个主体 + 7 个可选字段**，写哪些就显示哪些。

| 字段 | 中文别名（都认） | 英文别名 | 用在 | 示例 |
|---|---|---|---|---|
| **主体**（无字段名的那一行） | — | — | 全部 | `abandon` / `take part in` / `Good habits are hard to form.` |
| 音标 | 音标、发音 | ph, ipa, phonetic, pron | 单词 | `/əˈbændən/` |
| 词性 | 词性、词类 | pos, partofspeech | 单词 | `v.` / `n. / v.` |
| 释义 | 释义、意思、中文、含义、翻译 | meaning, cn, trans | 全部 | `抛弃，放弃；遗弃` |
| 例句 | 例句、例子、例 | example, eg, sent | 单词 / 短语 | `He abandoned his car and walked home.` |
| 例句翻译 | 例句翻译、例句释义、例译 | examplecn, egcn | 单词 / 短语 | `他弃车步行回家。` |
| 语法 | 语法、语法点、知识点 | grammar | 句子 | `be hard to do 结构，不定式作状语` |
| 备注 | 备注、说明、注释 | note, tip | 全部 | `后接名词或动名词` |

**语法的安全性**：字段名**可以缩写、可以中英混用、可以大小写随意**（`word`/`Word`/`WORD` 都行）。因为字段名认不出来也不报错——那一行会原样显示出来。所以老师的每一步尝试都有正反馈，不会"改完没反应"。

### 6.2 自动推断 vs 下拉切换模式？

**结论：自动推断（并允许每条记录显式指定覆盖）。不要给老师"先选模式"的下拉框。**

理由是把两种方案的失败模式摊开看：

| | 自动推断 | 手动"模式"下拉 |
|---|---|---|
| 老师需要做的操作 | **零** | 每换一种内容都要先切模式 |
| 忘切模式的后果 | 不存在 | 屏幕显示错或空白，老师不知道该怎么办 |
| 数据结构复杂度 | 一套字段 | 三套字段（老师要记三套） |
| 出错的定位难度 | 显示不好看 | "为什么什么都没显示？"——真正的灾难 |

**推断规则（简单、可解释、够用）：**

```
有 音标 或 词性                  → 单词卡（主体大字 + 音标 + 词性 + 释义 + 例句）
主体含空格且 ≥4 个词，或结尾是 . ? !  → 句子卡（整句居中大字 + 释义 + 语法）
其余（2–3 个词）                 → 短语卡（主体大字 + 释义 + 例句）
```

**允许显式覆盖**：给一条记录写 `类型: 句子`（别名 `type`）就强制当作句子，推断失效时老师有个"手动挡"。但**不把这个暴露成一个必须做的步骤**。

**界面上唯一的下拉框应该只做"筛选"，不做"模式"**：`显示：全部 / 只有单词 / 只有短语 / 只有句子`。老师想连着讲 20 个单词时，可以过滤掉句子。这个下拉**默认"全部"**，所以它是一个"可选加速器"，而不是必经步骤。

### 6.3 三种形式在屏幕上的排版建议

| | 单词卡 | 短语卡 | 句子卡 |
|---|---|---|---|
| 主体字号 | 极大（后面排也看得清，约 88–120pt） | 大（约 72–96pt） | 中偏大（约 48–64pt，因为句子长） |
| 主体换行 | 不需要 | 可能需要 | 必须自动换行，且按语义（不要在 `hard to | form` 中间断） |
| 音标 | 主体下方小一号 | 无 | 无 |
| 词性 | 与音标同行，灰色 | 无 | 无 |
| 释义 | 中号，醒目色（如浅黄） | 中号 | 中号 |
| 例句 | 小号，灰色，斜体 | 小号 | 无 |
| 例句翻译 | 更小，更灰 | 更小 | 无 |
| 语法 | 无 | 无 | 中号，带一个"语法"标签色块 |
| 备注 | 底部小字 | 底部小字 | 底部小字 |
| 最多显示几行 | 全部 | 全部 | 主体最多 3 行，超出自动缩字号 |

**课堂可读性优先**：与其让老师手动调很多东西，不如**只给一个 A+ / A- 字号总开关**，整体等比缩放。判定"后排看不清"应该是老师按一下 A+ 就能解决的，不要让他去调 8 个独立字号。

**`words.rs` —— 词表加载**（本报告第 5 节的规则 + 已跑通 14 个单测的实现）

```rust
pub struct Card { pub head: String, pub fields: Vec<(String, String)>, pub extras: Vec<String> }
pub struct Warning { pub line: usize, pub text: String, pub msg: String }

/// 永不返回 Err。空文件也返回空列表 + 提示。
pub fn parse(text: &str) -> (Vec<Card>, Vec<Warning>);
pub fn read_text_any_encoding(path: &Path) -> Option<String>;  // UTF-8 / GBK 自动识别
pub fn load_all(dir: &Path) -> Vec<WordFile>;                  // 扫描 .txt/.json
```

### 7.4 我没有验证的事（到教室后请逐条实测）

诚实起见，以下几条**本次调研没有条件在真实一体机上验证**，都属于"可能一票否决"的风险点，建议第一次进教室花 10 分钟按顺序测：

1. **透明窗口在目标一体机上是否真的透明。** 本机只验证了 API 存在、程序能编译运行不 panic，没有验证老核显/老驱动下的视觉效果。若透明失效（最常见的表现是变纯黑背景），退路：改成"纯色圆角卡片"（不透明），功能不受影响，只是没那么好看。
2. **置顶窗口能否盖在 PowerPoint 放映画面之上。** 这取决于 PPT 放映窗口自身的层级策略，本报告未实测。测法：打开 PPT 全屏放映，看悬浮窗是否在画面上方。若被盖住，退路：老师在"窗口播放"(非全屏)模式下用 PPT，或者用 Ctrl+Alt+H 切换。
3. **一级/二级防御对 PPT 翻页的实际影响。** 测法：悬浮窗盖住屏幕右下角，点 PPT 空白处翻页，确认点不到悬浮窗时 PPT 正常翻页。
4. **触摸点击的准确度。** 测法：64pt 的按钮连点 20 次，看有没有漏点。若漏点明显，把按钮加到 80pt。
5. **系统 DPI 缩放的实际值。** 测法：程序里打印 `ctx.pixels_per_point()`（本机实测日志里是 `ppp=1.000`，缩放 100%）。若一体机是 4K + 100%，默认字号要调大。
6. **教室机器上是否已经装了 VC++ 运行库。** 测法：直接双击 exe。若报"找不到 VCRUNTIME140.dll"，说明 `+crt-static` 没生效（回去检查 `.cargo/config.toml` 是否在**项目根目录**的 `.cargo` 文件夹里、且做了全量重编译）。
7. **杀软是否拦截。** 测法：首次双击时观察 Defender 弹窗。
8. **全局快捷键是否被其他软件占用**（一体机上常驻的"班班通"客户端、输入法、屏幕广播软件都可能抢占热键）。测法：注册快捷键后按一下，看有没有反应；不灵就换组合（`Ctrl+Alt+H` → `Ctrl+Shift+Alt+H`）。

## 8. 结论与建议（给动手时的自己）

1. **技术路线**：Rust + **eframe 0.36 / egui**（`glow` 后端，关掉 wgpu/wayland/x11/accesskit 默认特性）+ `encoding_rs`。别的框架在"透明 + 置顶 + 无边框 + **运行时可切换的鼠标穿透**"这四项上要么缺、要么要自己写 Win32。
2. **形态**：无边框半透明小窗（右下角、可拖拽、不抢焦点）+ 同窗口的展开式控制面板；托盘/全局快捷键只作兜底。
3. **部署**：单 exe + 同目录 TXT；`+crt-static`；配置和词表都在 exe 旁边；所有写失败静默忽略。
4. **数据**：宽容 TXT 为主、JSON 为辅；**格式错误的传播范围必须限制在一行内**；读文件要能认 GBK。
5. **内容形式**：一套字段集 + 自动推断，界面上只给"筛选"下拉，不给"模式"下拉。
6. **第一版**：只做"上下条 + 字号 + 隐藏"，**砍掉穿透和托盘**。

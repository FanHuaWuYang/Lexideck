## 一、这东西是干什么的

装在**班级的电子一体机**上，上课时在屏幕上以**悬浮小窗**形式展示英语内容。

**首要需求（慕言原话）**：
> 首先让英语老师能够自己决定展示什么内容。

由此定下架构原则：

> **程序只负责显示，内容全在外部文件里。**
> 老师给它一个文件，它就照着显示；换内容 = 换文件，不用重新编译、不用改程序。

## 二、已敲定的形态

**无边框悬浮小窗 + 控制面板**

- 可拖拽、可缩放、可调透明度、可置顶
- 控制面板含：词表切换 / 上一条·下一条 / 自动切换间隔 / 字号 / 置顶开关
- Nova 补充建议：面板里加一个**一键隐藏/呼出**（见第四节）

**内容形式做成几种"样式"，界面上用一个下拉切换**

候选（待定稿）：

- **单词卡片** —— 词 + 音标 + 词性 + 释义（+ 例句）
- **句子** —— 整句 + 翻译 / 语法点
- **短语搭配** —— 固定搭配 + 用法
- **中英对照** —— 一句中文配一句英文

❓待定：最后保留哪几种

> **调研后的修正建议（2026-09-17）**：不设"模式"概念，改用**一套统一字段 + 自动推断**（有音标/词性→单词卡；主体含空格且是整句→句子卡；其余→短语卡）。界面上那个下拉**只做筛选**（全部/单词/短语/句子），不做模式切换 —— 因为"忘切就白屏"是个纯自杀式失败模式。

## 三、数据文件

- **外部 JSON 或 TXT 文件**（慕言指定），老师用普通文本编辑器自己改
- **Nova 建议：TXT 当主推、JSON 当备选**
  - 理由：JSON 少一个逗号、多一个引号就整体解析失败，而且报错信息老师看不懂
  - TXT 用"一行一条"的约定，几乎改不坏
- **格式必须抗改**：能读的部分照常显示，出错只在一个角落安静提示，**绝不白屏**
- ❓待定：一体机是否允许安装软件 → 决定用安装包还是绿色免安装

### 结论

| 项 | 选定 |
|---|---|
| 框架 | **Rust + egui / eframe 0.36（glow / OpenGL 后端）** + `encoding_rs` |
| 形态 | 无边框半透明置顶小窗 + **同窗口展开式控制面板**（不做双窗口） |
| 部署 | **绿色单 exe**，`+crt-static` 静态链接 VC 运行库 |
| 词表 | **外部 TXT 为主**（宽容格式）+ 内置默认词表兜底；JSON 仅作高级可选 |
| 内容形式 | **一套统一字段 + 自动推断**（单词卡 / 短语卡 / 句子卡） |

**为什么是 egui**：只有它把「无边框 + 逐像素透明 + 置顶 + 拖拽 + 运行时可切换的鼠标穿透」全做成了现成 API，其余框架要么缺、要么得自己写 Win32。它也是唯一对 Rust 新手友好的（立即模式）。

**词表格式的取舍标准换了一条**：不看表达能力，看**错误的传播范围**。JSON 少一个逗号 → 整份文件失效、一个字都显示不出来；宽容 TXT 则**一行写坏只影响那一行**。

**自动推断取代"选模式"**：手动切模式会制造一个失败模式（忘切就白屏），自动推断老师零操作。界面上那个下拉因此只做**筛选**（全部 / 单词 / 短语 / 句子），不是必经步骤。

## 八、入场动画（2026-09-18 追加）

**慕言的原话**：

> 不是需要保留 3D 的那个粒子云，主要是一些窗口的进入、淡出，那种闪烁的非线性动画。就是先闪现，然后一个蒙版退出，然后再用非线性的动画让那个蒙版退出，然后展示内容的这种动画。

### 结论：不用 WebGL，egui 原生就够

> ⚠️ **更正**：本节最初一版记成了「复刻官网 3D 粒子云」，**方向错了** —— 他要的是**窗口入场动画**，不是 3D 点云。粒子那条路技术上也能走（要走 glow 自己写着色器），但**与他的真实需求无关**，优先级远低于本节。

技术上是三件东西：

```
① 帧驱动       ctx.request_repaint() 每帧重画
               （egui 是立即模式，天然合适）
② 非线性缓动   手写几个函数：easeOutExpo / easeOutQuint / easeInOutCubic
               约几十行
③ 蒙版         Painter::rect_filled 画遮罩，或 with_clip_rect() 裁内容区
```

闪现 = 1~2 帧的 alpha 抖动。**不涉及 WebGL / 着色器 / three.js。**

**性能开销几乎为零**（每帧画几个矩形），老一体机毫无压力 —— 与粒子云完全是两个量级。

### 时序设计（2026-09-19 按慕言的补充细化）

**慕言的原话**：

> 我想的是把终末地官网的两个东西结合到一起。第一个是闪烁，第二个是桌面上那种小窗 ——
> 先闪烁出一个黄色的方块，然后方块再滑出／划出，让方块划出、留下内容的那种。

**拆解**：

1. **黄色方块** —— 用终末地那支荧光黄 `#FFFA00`（与 official-v4 主题一致）
2. **闪烁** —— 方块出现前一两帧的亮闪
3. **方块滑出 → 留下内容** —— 这就是「**擦除揭示（wipe reveal）**」：
   方块扫过的区域露出内容，没扫到的区域仍是遮罩

```
t = 0.00~0.06   整个区域闪一下（白 / 亮黄）
t = 0.06~0.10   黄色方块从一侧出现
t = 0.10~0.45   方块非线性扫过（easeOutExpo / easeInOutCubic）
                方块已扫过的部分 = 露出内容；未扫到的部分 = 仍是遮罩
t = 0.45~0.55   方块滑出屏幕
t = 0.55~0.70   内容轻微淡入 + 上移几像素
t ≈ 0.70        静止
```

整段约 **0.7 秒** —— 短到不耽误老师，又足以让人感觉到"这个东西是被打开的"。

**实现要点**：方块 = 用画笔填一个矩形；揭示 = 裁切内容显示区，或把遮罩画在方块未扫到的一侧。**不涉及 WebGL。**

**已确定（2026-09-19）**：方块**从左向右**扫。

### 缓动曲线怎么选

所谓"动画曲线"就是一个把进度 `0→1` 映射成 `0→1` 的函数，用法只有一行：

```rust
// progress 是 0~1 的时间进度，curve() 是曲线函数
let x = x_start + (x_end - x_start) * curve(progress);
```

同一个进度值，喂给不同的曲线，方块的位置就完全不同。

| 曲线 | 感觉 | 适不适合 |
|---|---|---|
| `linear` | 匀速 | ✗ 太平，像进度条 |
| **`easeOutExpo`** | 极快起步，急速减速，"唰"地扫过然后稳稳停住 | ✓ **首选**，最有工业感 |
| `easeOutQuint` | 同上但稍柔和一点 | ✓ 备选 |
| `easeInOutCubic` | 慢起 → 加速 → 慢停，优雅 | ✓ 觉得 expo 太冲时用 |
| **`easeOutBack`** | 扫过头一点再弹回来，"咔哒"一声定位 | ✓ **想要机械定位感就用它** |
| `easeOutElastic` | 强烈来回弹 | ✗ 太花哨，不像工具 |

**推荐**：主扫用 `easeOutExpo`；如果希望有个"到位"的机械感，换 `easeOutBack`。
内容最后那段淡入上移另用更缓的 `easeOutCubic`（约 0.15 秒）。

```text
easeOutExpo(t)    = 1 - 2^(-10t)
easeOutQuint(t)   = 1 - (1-t)^5
easeOutCubic(t)   = 1 - (1-t)^3
easeInOutCubic(t) = t<0.5 ? 4t³ : 1 - (-2t+2)³/2
easeOutBack(t)    = 1 + c3*(t-1)³ + c1*(t-1)²     // c1=1.70158, c3=c1+1
```

（都是纯数学，几十行写完，不依赖任何库。）

### ⭐ 闪烁的确切定义（2026-09-19 从官网 CSS 扒到的原版）

**不要加载界面** —— 慕言 2026-09-19 明确：只要「色块移开、留下内容」这一段，而**色块的出现**用官网切角色立绘那种闪烁。

**扒取方法**：在官网干员页遍历 `document.styleSheets`，读 `CSSKeyframesRule` 的 `name` 与逐帧 `cssText`。
四个模块（`03-gameplay` / `04-finalpage` / `05-Gameplay` / `08-AIC`）用的是**同一份**：

```css
@keyframes flashing {          /* animation: 1s ease-out 0s 1 normal forwards */
  0%   { opacity: 0;   }
  10%  { opacity: .5;  }
  11%  { opacity: 0;   }   /* 闪 */
  20%  { opacity: .5;  }
  21%  { opacity: 0;   }   /* 闪 */
  40%  { opacity: .5;  }
  41%  { opacity: 0;   }   /* 闪 */
  100% { opacity: 1;   }
}
```

**要抓住的三个特征**（少一个就不像）：
1. **峰值只有 0.5**（半透明），不是全亮 —— 最后 100% 才到 1
2. **每一下都是"突降归零"**（10%→11% 直接 0.5 掉到 0），不是渐变回去
3. **间隔 0.10 → 0.20 → 0.40 越来越疏**，不是等距闪

照搬时把这段做成一个 `flashing(u)` 分段线性函数即可，Rust 与网页一致。

### 武陵城是什么调

它是终末地的「水利之城」，官方用来讲**现代国风**的那张牌。多方美术分析的定性：

### ★ 动画曲线：鹰角实际用的是 `ease`，不是花哨缓动

**扒取方法**：打开官网 → 遍历 `document.styleSheets` → 收集所有 `transition` / `animation` 里的 `cubic-bezier()`。

**明日方舟官网（`ak.hypergryph.com`）实测**：

```
transition / animation 共 9 处
其中带自定义 cubic-bezier：0 处
→ 全部用 CSS 默认的 ease
```

**终末地官网**（早前扒「切角色立绘」时记录的）：`transition:transform .4s .2s` —— 同样**没写 timing-function，即默认 `ease`**。

#### 结论：层次靠「错峰」，不靠缓动

```
.divider::before   transform: translateX(100%) → transition: transform .4s .2s
.title             opacity 0 / translateX(2rem) → transition: transform .3s .5s, opacity .3s .5s
.subtitle                                          （再晚 0.1s）
```

三个元素**都用 `ease`**，靠 **delay 差（0.2s → 0.5s → 0.6s）** 和 **时长差（0.4s vs 0.3s）** 做出先后。

**⇒ 这意味着我们的预演页需要修正。**

| 预演页里我放的（自套的） | 鹰角实际用的 |
|---|---|
| `easeInOutCubic` | **`ease`** |
| `easeInCubic` | — |
| `easeInOutQuint` | — |
| `easeOutExpo` | — |
| `linear` | — |

`ease` 本身是 `cubic-bezier(0.25, 0.1, 0.25, 1)`：**起步略缓 → 中段快 → 收尾平缓**。
比 `linear` 有"重量"，又不像 `expo` 那样收尾拖得过分。

**慕言 2026-09-19 的判断是对的**：「都是些动画曲线和《明日方舟》有一些差别」—— 差别就在于**鹰角基本不用自定义曲线**。

### 渲染大坑：冷启动「乱字」（已解决）

**症状**：新版词卡冷启动必现一团乱字（放大看像是控制面板内容被非等比压扁塞进悬浮窗）；字号/行位/颜色全对，但**每个字的形状都是错的**；随便点一下控制面板就恢复正常；控制面板本身渲染正常。

**排查弯路**：先按「两个窗口的绘制画串了」方向查，在 `ui()` 里加过三种「当前在画哪个窗口」的守卫（窗口编号 / 父子关系 / 画布尺寸）——全部无效；实测 `App::ui` 每帧只调用一次、只带主窗口的 Ui，那些守卫是死代码。

**真因**：词卡排版（Galley）在主窗口那一帧预先做好、拿到悬浮窗再画 —— **字形 UV 绑定的是「排版那一刻」的字体图集状态，跨一帧就取错位置**。位置对、字形错，就是它。

**修法**（三项，全部就位）：
1. 排版计划**惰性重建**：窗口尺寸估算可以借一次排版量高度（量完丢弃），真正的排版在悬浮窗自己的绘制回调里做；
2. 悬浮窗入场动画**由悬浮窗自己驱动**（原来只靠主窗 300ms 的帧率，扫出动画会卡在半路）；
3. 动画计时起点改为**窗口第一帧真正画出**时（窗口创建到出现有几百毫秒延迟，创建那刻计时会吃掉大半个闪烁段）。

由 dsh 完成修复并逐帧验证（窗口 0.92s 出现 → 闪烁 → 扫出 → 2.63s 静止，全程自驱）；Nova 复验：冷启动零点击渲染正确、`cargo test` **30/30 通过**。

**状态：词卡版式 v0.6 + 字号/分辨率适配 + 渲染修复全部就位。待办：回校后一体机实测（4K 比例、透明、置顶、触摸目标、色板可读性）。**

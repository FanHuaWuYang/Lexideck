| 面板动作 | 通道 | app 侧行为 |

## 7 验收后修的三处（慕言真机反馈）

真机跑起来之后慕言反馈了三件事，都在这一轮修掉并复验：

### 7.1 滚动条盖住内容（"占据左侧的一点位置…占掉字或者某个元素的边框"）

- 根因两条：① egui 的滚动条默认是 `ScrollStyle::default()` = **floating**，它是**浮在内容上**画的，
  所以必然压住右边那点文字／元素边框；② `foreground_color` 默认 true → 滑块取
  `widgets.*.fg_stroke`，而我们把 fg_stroke 设成了正文色（近黑 `#202428`），于是白面板上就是一条黑条。
- 修法：`ctx.all_styles_mut(|st| ...)`（egui 0.36 **没有** `Context::style_mut`，要改两套主题就用这个）
  里设 `sc.floating = false`（改成占自己一条道，内容自动让出宽度）＋ `sc.foreground_color = false`
  ＋ `bar_width 8 / handle_min_length 28 / bar_inner_margin 4`；轨道色 = 面板底色，滑块色走
  `widgets.*.bg_fill`。

### 7.2 卡片入场动画变卡

- 根因不是渲染，是**抢帧**：一个 eframe 进程里所有 viewport 在同一趟 `update()` 里渲染。P2b 在面板里
  写了「只要有卡片在动画就 `ctx.request_repaint()`」——它重绘**所有**视口，于是每帧绘制很重的面板
  也被拉进全速渲染，把卡片动画的帧率压下去。
- 修法：面板固定 `request_repaint_after(300ms)`（点击会自然触发重绘）；卡片动画只由各自视口
  `request_repaint_of` 驱动（`draw_floats` 里本来就有）。
- 实测（点一次「重播动画」后采样 4 秒的 `TotalProcessorTime` 增量）：**1.328s → 0.438s**。

### 7.3 策略行第二行的来源标签"像下一个元素的"

- 根因：第一行 52px 是触摸规格（≥50），词的下方本来就有留白；而第二行标签原来是在第二行里
  **居中**（`l1.bottom() + PLAN_L2_H/2` = +14），结果标签中心距**自己那行的词**和距**下一行的词**
  几乎一样远（实测 40 : 40），看起来就不属于上面那行。
- 修法：新增 `PLAN_L2_CHIP_DY = 6.0`（标签中心相对第一行下缘），实测变成 **32 : 49**；
  同时把行的高亮与点击区从第一行 `l1` 扩到整行 `rect`（否则上提后的标签会被高亮带从中间切断）。
- 画像证据：竖扫像素（`lx_col_scan.ps1`）定出分隔线间距 = **80px**（= 52 + 28，1:1 无缩放）、
  日期段 chip 528–549（中心 539 = 第一行中心）、来源标签 560–582（中心 571）；
  鼠标停在行内时整行底色 514–592 一致（`#EDF4F2`），确认高亮不再断开。
  注：PowerShell 里 `byte -shl 16` 会在 byte 域内截断（只剩 B 通道），取色前要先 `[int]`。

### 7.4 卡片入场动画只有 29fps（慕言："最后想点办法优化帧率表现"）

- **先验证机制再动手**：卡片浮窗是 `show_viewport_immediate` 的**即时视口**，它和面板在**同一趟**
  `ui()` 里出图 —— 所以动画帧率 = 面板那一趟的帧率。加了个按来源分开记帧间隔的探针
  （环境变量 `LEXIDECK_FPS_LOG=<文件>`，每行 `root|card 毫秒`），实测两边帧间隔**逐个相同**
  （34.5ms : 34.5ms），把这条机制钉死了。
- **根因**：`[profile.dev]` 没配 → 默认 `opt-level 0`，egui/epaint 的排版与三角化全在跑未优化代码。
  面板每帧 34.5ms → 动画 29fps（16.7ms 的 vsync 预算根本没够着，直接掉到 30fps 档）。
- **改动**：
  1. `Cargo.toml`：`[profile.dev] opt-level = 1` + `[profile.dev.package."*"] opt-level = 3`（依赖才是每帧大头，自己代码留 1 保住调试信息）。
  2. 新增设置项 `vsync`（`设置.txt` 键 + 设置页「动画流畅度」两档）。注意 eframe 0.36 的
     `NativeOptions` **没有** `vsync` 字段，在 `opts.glow_options.vsync` 里；这一项启动时读取，改完要重开。
  3. 面板自己不再在卡片动画期间全速重绘（见 7.2）。
- **实测**（同一台机器、同一测法：启动后 8 秒内所有帧间隔）：

  | 构建 | vsync | 动画帧率 | 每帧中位数 | p95 |
  |---|---|---|---|---|
  | 改前：debug（opt-level 0） | 开 | 29.0 fps | 33.4ms | 41.5ms |
  | 改后：debug（依赖 opt-level 3） | 开 | 118.3 fps | 7.9ms | 10.8ms |
  | 改后：debug | 关 | 177.1 fps | 5.2ms | 8.6ms |

- **两道天花板**：① 每帧成本（上面这条，主瓶颈）；② vsync = 卡片所在那块屏的刷新率
  （这台是 60Hz + 165Hz 各一块，所以 60Hz 屏上 60 帧就是满帧，165Hz 屏上还能往上）。
- 探针是常驻的诊断能力（没设环境变量时零开销），统计脚本 `lx_fps_stat.py`。

## 8 没验到的 / 留给下一轮

- 触摸屏真机手势（全部验证都在鼠标下做的，触摸只有「控件高度 ≥34px」这条静态保证）。
- 屏缩放 ≠100% 与多显示器下的坐标／DPI 表现。
- 「重播动画」只抓到一帧中间态，没有逐帧确认时长与错峰是否符合预期。
- 层级切到「置顶」时，**真的把 PPT 全屏盖住**这件事没在 PPT 上跑（用 ex 样式的 topmost/transparent 佐证）。
- 策略条数很多（>8）时的滚动与分段标题黏性没有专门验。

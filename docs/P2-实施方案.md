## 已定的决策（含 Nova 补充）

### 1. 一条「策略」是什么 ✅ 慕言已定

**一条策略 = 一个词的一段展示时间（词 + 日期段）**，也就是主库里一条 `display_time` 项里的一段。
「永久关闭」的粒度就是它：关掉 = 这个词在这段时间不上屏，与别的词、该词别的日期段无关。
主库里同一个词可以有多条日期段，每段各自是一条策略行。

### 2. 来源文件怎么来（Nova 补充）

主库里的展示时间项没有"从哪份文件来"的信息。P2 给它加一个只作展示用的标签 `source`
（导入时把 `deck_name` 记进去；没写就是「未命名」）。它**不参与**冲突判定（键仍是 词+日期段），
老的 `lexideck.json` 没有这个字段也能正常读。

### 3. 关闭状态存哪（Nova 补充）

设计说"记在 exe 同目录的状态文件里"，新增 **`状态.json`**：

```json
{ "version": 1, "off": [ { "word": "seek", "from": "2026-10-06", "to": "2026-10-12" } ] }
```

- 键 = 词（小写）+ 日期段；`off` 里的策略不出卡片，**写进文件就是永久的**，直到在面板里手动打开。
- 与 `设置.txt` 分开：`设置.txt` 是"人的偏好"，`状态.json` 是"程序运行态"。
- 文件读不懂时按"没有关闭项"处理，并且**不覆盖**它（避免把坏文件写没）。

### 4. 本地日期从哪来（Nova 补充）

不引第三方日期库（依赖树里本来就没有）。这个软件只跑 Windows，直接用 `kernel32` 的
`GetLocalTime` 取本机本地日期 —— 没有时区换算、没有夏令时算错的余地。日期比较用 `(年,月,日)` 元组；
"还剩几天"用一个自带的"公历 → 天数"小函数算。

**测试开关**：设环境变量 `LEXIDECK_TODAY=2026-10-06` 就当成那天，用来验证换批、空白日、已结束折叠，
不用真去改系统时钟。（他改系统日期也能验，这是给自动化测试和演示用的。）

### 5. 屏幕上到底放什么（Nova 补充，须与"立即展示"共存）

屏幕内容有两种来源，程序自己的状态里记着当前是哪种：

| 来源 | 什么时候 | 内容 |
|---|---|---|
| **今日（自动）** | 启动时、跨日时 | 今天生效的策略（去掉被关闭的），按主库顺序，放不下按顺序截断 |
| **手动** | 点「立即展示」之后 | 只显示勾选的那几个词（P1 行为），面板标注"手动展示" |

卡片板块给一个「按今日展示」按钮切回自动。**当天没有任何策略生效 → 屏幕清空**
（不沿用上一批、不留旧卡片），这与设计 §3.3 一致。

排序用**主库里展示时间的先后**（先导入的先上屏），这样"截断哪几个"是可预期、可复现的。
同一天同一词的多段都生效时，策略内的隐藏项取**并集**。

### 6. 排序与"今日生效 N 个 / 已显示 M 个"（设计 §5.1）

面板底部与卡片板块都要显示这两个数；截断规则沿用 P1 的平铺算法。

## 实施顺序

| 批次 | 内容 | 完成判据 |
|---|---|---|
| **P2a** | 引擎与状态：本机日期、按日解析生效集合、`状态.json`、app 接入（启动上屏／跨日换批／空白日）、层级两档 | 单测覆盖日期解析/生效/关闭/截断；跑起来用 `LEXIDECK_TODAY` 换日期能换批、空白日真的空 |
| **P2b** | 面板三板块改造：策略（当前/未来/已结束折叠 + 开关）、卡片（清单 + 按今日展示）、设置（层级两档） | 截图核对 + 离屏渲染测试；关掉一条策略后卡片真的消失且重启仍关着 |
| **P2c** | 未匹配展示时间逐个弹窗（含「剩下的都跳过」）、边界项 E4／E5／E6 | 单测 + 无头渲染 |

每批结束都要：`cargo fmt` → `cargo test` 全过 → 真跑截图 → 更新 `docs/开发记录-P2.md`。

## 注意（上一轮踩过的坑）

- 构建前先 `echo $CARGO_TARGET_DIR`，非空就 `unset`（子 agent 留下的环境变量会让产物写到别处，白验一轮）。
- 两行文字的块要用**确定高度的盒子**，别用会吃掉整块高度的竖向容器。
- 单测写临时文件按进程号唯一化（本机 `TMPDIR` 是多进程共用的）。
- 测试数据**绝不写进** `target/debug/设置.txt`（那是他实际运行的配置）。
